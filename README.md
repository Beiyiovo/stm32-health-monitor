# STM32 健康监测设备（毕业设计）

> 基于 **STM32F103C8T6** 的多参数健康监测设备原型：采集体温 / 心率血氧 / 运动姿态，
> 在 OLED 上本地显示，并通过 ESP32-C3 无线上报，异常时蜂鸣器与 LED 报警。
>
> 状态：**开发中**。外设驱动逐个验证，完整主程序 `09_main` 尚未整机联调。

最近更新：2026-10-06

---

## 硬件

| 模块 | 型号 | 接口 | 作用 |
|---|---|---|---|
| 主控 | STM32F103C8T6（蓝板） | — | 采集、显示、报警、串口通信 |
| 显示 | SSD1306 OLED 128×64 | I2C（**软件模拟**） | 本地显示 |
| 体温 | DS18B20 | 单总线 | 体表温度 |
| 姿态/计步 | MPU6050 | I2C | 加速度、步数 |
| 心率血氧 | MAX30102 | I2C | 心率、血氧饱和度 |
| 无线 | ESP32-C3 | UART（串口2） | 数据上报手机/上位机 |
| 报警 | 蜂鸣器 + LED + 按键 | GPIO | 阈值报警与交互 |

工具链：Keil MDK-ARM 5.42　|　烧录：串口 ISP（BOOT0 + 复位键）

## 工程亮点：一次完整的 I2C 总线排查

这是本项目最有价值的一段，完整记录在 [`说明.md`](说明.md)。

**症状**：扫描不到任何 I2C 设备，但电压正常、引脚能拉高拉低、连线全通。

**定位到的三个根因**：

1. **硬件 I2C 外设不可靠**（STM32F103 的经典问题）→ 改为 **GPIO 软件模拟 I2C**
2. **总线速率太快** → `I2C_DELAY_US = 20`（≈25 kHz）才稳定，5 μs（≈100 kHz）扫不到
   - 物理解释：面包板 + 杜邦线的分布电容远大于 PCB，I2C 是开漏总线，上升沿靠上拉电阻给电容充电，
     速率快时电平还没建立主机就采样 → 从机收到乱码 → 不应答
3. **`I2C_Send7bitAddress` 实际要传 8 位地址** → 之前扫到 0x78/0x79（8 位）而非期望的 0x3C（7 位）

**诊断方法**：用 `16_i2c_scope`（自己写的软件示波器）把每一位电平打印出来，
观察第 9 位 ACK 时 SDA 是否被从机拉低 → 实测 0x3C 的 ACK=1，证明模块与总线都是好的，问题在主控侧。

> 同一限制也影响烧录：串口 ISP 用 9600 最稳，115200 从未成功过。

## 快速开始

1. Keil MDK-ARM 5 打开想验证的工程，例如 `01_uart/step1_uart.uvprojx`
2. 编译（全部工程应 0 错误 0 警告）
3. 烧录（串口 ISP）：

   ```
   ① BOOT0 跳线帽 → 1
   ② 按一下复位键 RST
   ③ 双击 flash_any.bat → 输入工程编号 → 回车
   ④ 反复按复位键，直到屏幕显示「连上了」
   ⑤ 烧完：BOOT0 → 0
   ⑥ 再按一下复位键      ← 这两步漏了程序不会跑
   ```

   > 建议改用 ST-Link V2：按 F8 三秒烧完，不用拨跳线、不用按复位。

4. 串口监控：`serial_log.bat`
